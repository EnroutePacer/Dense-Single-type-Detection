# 密集单类别检测的研究假设

> **Historical snapshot / superseded（2026-10-10）**：旧 H2“主要发生在 decoder”和“零推理开销”均未被证实。当前把 generation、selection、decoder、output 作为并列竞争解释，见 [假设注册表](../hypotheses/README.md)。

## 项目定位

表格单元格不是研究终点，而是高密度、单类别、强规则结构检测的验证基座。与 COCO 不同，这类任务的困难不是类别区分，而是：

- 单图 GT 数很高；
- 小框和相邻框密集；
- one-to-one query 容量接近 GT 数；
- 分类分数承担“可匹配性/定位质量”排序；
- evaluator、后处理和 query budget 都可能成为显式瓶颈。

## 当前证据支持的核心命题

DEIM 在普通数据集上用 Dense O2O 增加每图目标数，解决正样本稀疏。当前表格数据本身已经很密集，因此瓶颈可能发生迁移：

```text
稀疏自然图像：正样本数量不足
密集单类别图像：query/匹配容量、低质量匹配和置信度校准更突出
```

这比“给小框加权”更有论文潜力，但需要严格证据。

## 可证伪假设

### H1：密度存在最优区间，而不是越大越好

当每图 GT 接近或超过 query 数时，Mosaic 增加目标会降低 matched-GT 比例，收益转为负。应控制目标密度或让 query budget 随密度适配。

### H2：主要漏检发生在 decoder 重评分，而非 encoder 完全缺少候选

无 GT 诊断已看到大量 small query 进入 decoder 后低分。带 GT 诊断应验证真实漏检目标是否在 decoder 层逐渐掉分或错配。

### H3：单类别场景的分类头实际在学习 matchability

类别恒定时，分类 logit 主要表达“是不是目标”和定位质量。可以研究更直接的质量/可匹配性目标、排序损失或校准方式，而不是增加类别建模容量。

### H4：尺度增强需要按目标像素尺寸和密度联合调度

大尺度提高小框特征分辨率；缩小/拼接提高低分辨率鲁棒性并增加密度。二者可能需要 curriculum，而不是任意多尺度混合。

### H5：水平/垂直邻域结构可作为训练期约束，但不能依赖表格类别语义

若希望方法可推广到其他密集单类任务，结构项应定义为局部排斥、中心分布或重复框抑制，而不是只对表格行列有效的专用规则。

## 最有希望的研究组件

1. 密度感知 Mosaic：根据原图 GT 数选择拼接数或采样概率，避免超过 query budget。
2. level-balanced query selection：避免 encoder Top-K 过度被某尺度层垄断。
3. matchability-aware 单类别质量目标：显式对齐分类分数与匹配 IoU/最终可召回性。
4. 训练期重复预测排斥或局部覆盖约束：推理不增加成本。

这些目前都是候选假设，不是已完成贡献。

## 论文闭环要求

- 第一阶段：证明问题——GT 密度、matched ratio、Top-K survival、decoder score trajectory。
- 第二阶段：最简单干预——密度受控 Mosaic、正确 MAL 基线。
- 第三阶段：找副作用——query 饱和、重复框、不同密度分桶退化。
- 第四阶段：提出只解决该副作用的组件。
- 第五阶段：跨模型尺寸、跨数据集、三 seed、相同 epoch/steps 和零推理开销验证。
