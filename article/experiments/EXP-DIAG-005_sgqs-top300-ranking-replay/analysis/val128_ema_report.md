# SGQS e28–e34 固定 val128 EMA 回放分析

## 口径

- 只读取 `val.ema.gt.jsonl`，不混入 raw。
- 真 COCO 指标来自各 epoch `summary.json`；`APs/ARs@300` 与 `APs/ARs@640` 均采用 COCO 一对一匹配。
- 下文阶段 coverage 是逐 GT 独立的最佳 IoU 覆盖，不是一对一 COCO recall；同一 query 可以覆盖多个相邻 GT。
- COCO-small：原图 annotation `area < 32²`。
- hybrid-small：直接缩放至 640×640 后，`bbox area < 32² OR bbox short side < 16`。
- 阶段顺序：8084 个有效 dense candidate → 实际选择的 dense Top-640 → decoder 最终 640 query → 按分类分数取 decoder Top-300。

子集有 128 图、15,446 个非 crowd GT。COCO-small 430 个，hybrid-small 7,314 个；交集 323，COCO-only 107，hybrid-only 6,991。

## 前段收益与后段回跌定位

以下 COCO-small 结果在 IoU .50 和 .75 上完全相同。

### e28 → e29

- decoder Top-300：49 个 GT 获得覆盖、17 个失去覆盖，净 +32（+7.44 个百分点）。
- 49 个 gain 在 e28 的 decoder-all 中全部已有合格框，只是 rank>300；rank 中位数 `359→259`。
- 17 个 loss 中，15 个到 e29 时仍有 dense-all 合格框、但未进入实际 dense Top-640；另 2 个仍在 decoder-all、但跌到 rank>300。
- dense-all 净变化 0，dense Top-640 / decoder-all 反而分别净 -37 / -36。

因此前段收益不是“产生更多/更准候选”，而是把一部分原先位于 301–640 的 COCO-small 合格 query 提升进最终 Top-300；同时牺牲了另一部分 Top-640 广覆盖。

### e28 → e30

- decoder Top-300：35 gain、13 loss，净 +22（+5.12 个百分点）。
- 35 个 gain 在 e28 decoder-all 中也全部已覆盖；rank 中位数 `342→275`。
- 13 个 loss 到 e30 的去向：6 个在 dense-all 有合格候选但未入 dense Top-640，7 个仍在 decoder-all 但 rank>300。
- dense Top-640 / decoder-all 都净 -9，Top-300 却净 +22。

e30 相比 e29 的子集收益较弱，但机制相同：收益首次以正方向出现在最终 Top-300 排名阶段。

### e30 → e34

- decoder Top-300：11 gain、36 loss，净 -25（-5.81 个百分点）。
- 36 个 loss 在 e34 decoder-all 中全部仍有 IoU≥.75 的框，只是全部跌到 rank>300；rank 中位数 `271.5→338.5`。
- 同期 dense Top-640 和 decoder-all 都净 +9，不但没有退化，反而恢复。
- 11 个 gain 中，5 个在 e30 已位于 decoder-all 但 rank>300，6 个在 e30 仍有 dense-all 合格候选但未入 dense Top-640；到 e34 均进入 Top-300。

因此后段下跌的直接位置很明确：不是 dense 候选消失，不是 Top-640 生存率下降，也不是 decoder 定位崩塌，而是最终分类排序把一批原本 rank≤300 的 COCO-small query 推到 301–640。

## 两种 small 定义内部的交换

所有发生变化的 COCO-small GT 都属于 `COCO-small ∩ hybrid-small`；107 个 COCO-only GT 七轮在 Top-300 中始终 100% 覆盖。

IoU≥.50 的 Top-300 净转移：

| 区间 | COCO∩hybrid | COCO-only | hybrid-only | hybrid 合计 |
|---|---:|---:|---:|---:|
| e28→e29 | +32 | 0 | -46 | -14 |
| e28→e30 | +22 | 0 | -31 | -9 |
| e30→e34 | -25 | 0 | +61 | +36 |

这与一种“排序容量在两个 small 子群之间来回分配”的行为一致：e29/e30 更偏向 COCO∩hybrid，后期又偏回 hybrid-only。由于独立 coverage 不是 query 与 GT 的一对一归属，这里只能称为强关联的重分配信号，不能把净数机械解释为同一批 query 的逐一交换。

## 代表性与解释边界

- 128 图由固定 SHA256 规则从 val 非模型驱动抽样，适合严格跨 epoch 配对。
- 但 430 个 COCO-small 只分布在 17 张图；所有上述跨 epoch COCO-small 状态变化只发生在 image 11570 和 12461 两张图。它们分别有 480 和 320 个总 GT，正好都受 maxDets=300 强约束。
- 因此它对“排名/容量机制”是清晰反例和强证据，但不能估计该机制在完整验证集上的总体占比。子集 e29 比 e30 高 3.04 AP 点，而完整验证集二者仅差约 0.04 点，也显示抽样方差明显。
- 独立 GT coverage 不执行 COCO 的一对一匹配，不计重复 FP；不能代替 AP/AR。它与本子集 APs@300 七轮相关系数为 0.998，只说明它非常适合定位此子集的阶段差异。

要把结论提升为完整验证集定因，下一步应至少对 e28/e29/e30/e34 做同样的 full-val EMA GT 回放，并保存最终 query 的 score/rank 与匹配结果；若研究目标正式改为本地 hybrid-small，还必须统一重算 full-val custom hybrid AP，而不能用这里的独立 coverage 替代。
