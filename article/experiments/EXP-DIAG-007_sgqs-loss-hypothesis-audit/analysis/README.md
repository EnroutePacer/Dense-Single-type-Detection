# EXP-DIAG-007 详细分析与推理边界

## 1. 问题被拆成四条可核查链

本审计没有从 AP 曲线直接猜损失原因，而是依次核查：

1. **训练入口冲击**：SGQS/B0 同 batch 的 step-0 loss 是否只差新增项；
2. **整轮优化轨迹**：新增项、基础 Encoder/Decoder loss 是否在 e31 附近出现拐点；
3. **代理与终点是否同向**：owner coverage/survival/IoU 与正式 AP-small 是否同步；
4. **实现中的尺度权重**：dense 是否按所有 owner 统一归一化，还是按层固定等权。

输出端直接承载阶段不重新推断，沿用 EXP-DIAG-006 的 12,841 图正式一对一匹配结果。

## 2. 假说 1：强启动项成立，“近似过拟合”不成立

### 2.1 最干净的证据是 step 0

step 0 尚未执行参数更新，SGQS/B0 的基础 loss 各项完全相同；两臂总 loss 差
`5.0710819000`，与 SGQS 四项之和逐位一致。这排除了“首 batch 不同”或“基础 criterion
配置不同”对这一个数值的解释。新增项中 dense 占 `92.74%`，survival 因课程为零。

dense、owner L1 和 owner GIoU 从第一步即为全权重，配置里只有 survival 有 1 epoch
升温。因此可以写“恢复训练入口存在很强的新增目标冲击”。但 loss 是不同归一化后的标量；
它没有测到对共享参数的梯度范数、方向、裁剪和 AdamW 更新，不能写成“SGQS 获得 59.88%
的参数更新”。

### 2.2 指标表现是交换而非整体崩坏

e29/e30 的 AP-small 相对 B0 分别高 `2.4128/2.5399` 个百分点，AP-large 低
`0.8860/1.0534` 个百分点，总 AP 只低 `0.1950/0.0625` 个百分点。到 e34，SGQS 总 AP
高 `0.0915` 个百分点，AP-large 只低 `0.0255` 个百分点。若把“整体性能被侵蚀”定义为
最终整体 AP 低于配对 B0，数据直接反驳该表述。

### 2.3 为什么不能称过拟合

过拟合至少需要同一 checkpoint 的训练集/验证集同口径曲线，证明训练表现继续改善而验证
表现变差。当前固定 train128 没有完成七轮正式回放；训练 mini-batch loss 下降也可能只是
目标优化正常。因此本审计只保留“强启动冲击、快速排名重排”，不保留“几近过拟合”。

## 3. 假说 2：链路缺口成立，损失接管故事不成立

### 3.1 监督拓扑

SGQS 直接监督三处：全部 dense candidates 的分类、保留下来的唯一 owner 框、以及 owner
相对 Encoder Top-640 cutoff 的 survival。它没有保持同一 owner 身份穿过 Decoder 各层，
也没有直接监督最终 640 query 中该 GT 的分类排序必须进入 Top-300。

`protect_encoder_supervision` 还会删除与基础 Encoder 分类/框分配冲突的整个 SGQS owner
监督，而不会改变原 matcher。这一设计是“代理约束”，不是端到端硬保留。

### 3.2 代理越来越好、终点反而变差

e30→34 的 owner coverage、owner IoU、pre-TopK survival 全部提高，冲突比例下降；SGQS
四项 loss 也下降 `28.68%`。与此同时服务器日志 AP-small 下降 `0.023280`。完整本地 val
又显示 AP-small@640 上升、AP-small@300 下降，并将 93.38% 的 e30→34 loss 转移事件
定位为 `rank_gt300`。

因此最强的训练级相关证据是：**SGQS 优化的代理在持续达成，但它没有约束最终发生问题的
Top-300 admission。** 这与“缺少全链路跟进”一致。

### 3.3 没有基础 loss 在 e31 回升的证据

e30→34：

- base Encoder：`0.345238 → 0.258981`；
- base main Decoder：`0.382164 → 0.346942`；
- base pre：`0.166336 → 0.131146`。

三组都持续下降。总 base remainder 在 e33→34 只有 `8.432745 → 8.460535` 的 `0.33%`
小幅波动，主要总量受 DDF 项影响，时间上也晚于 e31 的 AP-small 首次大跌。这不能支持
“Encoder loss 足够小后，大框 AP 下跌触发基础 loss 回升”。此外 AP-large 是验证结果，
根本不进入反向传播；它只能与训练变化共同出现，不能作为触发器。

更合理的机制语言是：基础目标始终继续优化全体目标，而 SGQS 没有末端排名约束；两者在
有限 Top-300 预算上的优先级可以随参数/EMA 轨迹重新排列。

## 4. 假说 3：代码前提正确，但缺决定性观测量

### 4.1 实现事实

`engine/sgqs/criterion.py::_dense_loss` 对 P3/P4/P5 分别累计 positive/negative sum 和
count，每层独立除以本层 count，最后除以层数 3。这使层均值等权，而不是 owner 等权。

训练日志中的 kept owner/图为：

| epoch | P3 | P4 | P5 | P3/P5 |
|---:|---:|---:|---:|---:|
| 28 | 22.814 | 4.105 | 0.327 | 69.85 |
| 30 | 29.004 | 5.294 | 0.385 | 75.26 |
| 31 | 37.698 | 5.326 | 0.390 | 96.58 |
| 34 | 53.510 | 5.372 | 0.397 | 134.80 |

在正样本损失导数相同的理想比较下，同一步一条 P5 positive 与 P3 positive 的显式系数
之比为该步 `N_P3/N_P5`。表中的约 70--135 倍是用整轮平均 owner 数做量级估算，不是
逐 step 系数的精确平均。采样训练探针还显示，累计 P5 kept owner 的 98.91% 在增强后
large-input 组，所以“稀少大尺度 owner 高杠杆”不是凭空猜测。

### 4.2 为什么仍不能判定因果

当前探针只保存总 `loss_sgqs_dense`，没有保存 P3/P4/P5 各自的 positive/negative loss；
更没有保存它们对共享分类头、neck/backbone 参数的梯度。一个高归一化系数样本可以因为
误差很小而梯度仍小，也可能被其他层反向方向抵消，随后还会经历 gradient clipping 与
AdamW 状态缩放。

所以本审计把 H3 提升为最高优先级的**可测试实现机制**，但没有将其登记为回跌原因。

## 5. image 5367 为什么看起来与总体指标矛盾

该图含 622 个 GT，已经超过 formal `maxDets=300`。e29 的 640 query 中，local
hybrid-small 仍有 611 个，只比 e28 少 10；真正突变的是尾部：整像素取整后近似唯一框
从 623 降至 498，301--640 中与 Top-300 IoU>.9 的 query 从 8 增至 113，rank-500 分数
从 0.9839 降至 0.2969。rank-300 分数仍为 0.9859。

因此：

- 画 `score>0.5` 会少 168 个框；
- 画全部 640 时大量框与 Top-300 重叠，也会让未覆盖区域看起来“漏了”；
- 正式 evaluator 只消费高分 Top-300，没有 0.5 阈值，尾部塌陷不直接扣 AP；
- 对这种 622-GT 图，模型最多提交 300 个检测，AP 的关键本来就是哪 300 个被排到前面。

e29 的 Top-300 对 evaluator-small 更有利，所以总体 AP-small 可以上升，即使人工查看
640-query/阈值图时观感更差。这不是 evaluator 与图片矛盾，而是两者观察了不同排名区间。

29 张 query probe 具有相同方向的定性现象，但它们按 formal transition strata 选样，存在
明确选择偏差；总体发生率仍必须以 EXP-DIAG-006 full-val 表为准。

## 6. 当前最强工作模型与竞争解释

当前最强工作模型按证据强度排序：

1. **已确认**：无 dense/owner 升温的恢复训练启动冲击；
2. **已确认**：SGQS 代理指标持续改善但最终 Top-300 AP-small 回跌；
3. **已确认**：回跌的直接输出载体主要是最终 rank>300，而非全 640 几何消失；
4. **已确认**：dense 使用层均值等权，稀少 P5 单样本显式系数更大；
5. **尚未确认**：启动冲击是否造成泛化过拟合；
6. **尚未确认**：等层归一化的实际梯度是否主导共享参数；
7. **尚未确认**：EMA 是根因、放大器，还是只把在线参数轨迹平滑成更明显的倒 U。

因此论文或科研日志目前可以写“高可信机制假说”，不能写“已经找到训练级唯一根因”。
