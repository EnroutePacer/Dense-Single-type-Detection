# SGQS v2 中心/IoS与无接收者溢出修订

2026-10-27。基于5f56027代码核对和确定性合成样本检查，不是新的真实数据训练结果。

旧专项门控要求Encoder和Decoder均以IoU>=.5明确归属同GT。若GT面积为A，Decoder碎框完全在GT内且面积为.1A，则IoU=.1、IoS=1；若Decoder框包含GT且面积为4A，则IoU=.25、IoS=1。两者会被旧冗余门控遗漏。原有背景分类和可能适用的dense/回归监督仍在，不应称作完全无监督。

本修订将待罚候选改为原始网格anchor中心唯一位于GT内，Decoder IoS（交集/较小面积）>=.8且明确归属同GT。可靠代表和救援入口仍用IoU检查。保留正样本、有效owner、跨GT覆盖和GO冲突保护；包含多个GT的框及中心落在重叠GT内的候选不处罚。

有可执行跨GT接收者时沿用转移，不设数量下限。一张图完全没有配对时，按每GT除可靠代表外的TopK中心候选数n，先保留10个备用（未确认冗余者优先，再按Decoder定位质量、Decoder分数、来源索引），备用不按Encoder分数轮换；只从剩余安全冗余中选择至多max(n-10,0)个Encoder score>.8的候选，按置信度降序处罚到logit(.8)，无接收者升分。0.8/10为可配置首轮阈值，尚无最优性或收益证据。

测试覆盖：GT内碎框、包含GT大框、包含多个GT、原始中心位于GT外但回归框完美、中心重叠歧义、10/11/13备用边界、score恰等/低于阈值、受保护候选计数和处罚上限、任何可执行配对关闭整图fallback、transfer不受0.8/10限制、teacher detach、support关闭两分支、真实DFINE含DN前后向与同权重推理不变，以及双rank稀疏/overflow/混合/全空归一化。

检查结果见 [validation.json](validation.json)。日志中的donor_ios_only报告旧IoU逻辑遗漏而新门控接纳的安全候选数；它不是真实AP增益。更多被罚候选也不自动意味着困难实例改善。未运行真实训练、CUDA AMP/DDP或实际动态阈值部署。
