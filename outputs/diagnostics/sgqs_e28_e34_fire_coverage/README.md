# SGQS e28–e34：Encoder owner → Decoder 输出与“火力覆盖”

## 口径

- 权重：SGQS `checkpoint0028`–`checkpoint0034` 的 `ema.module`。
- 范围：完整验证集，12,841 张图、1,458,060 个 GT；其中 COCO-small 32,346 个。
- 局部 Encoder owner：对每个 GT，在 Encoder Top-640 中取 **Encoder 分数最高且 Encoder 框 IoU≥0.5** 的 query。
- query 身份：Encoder Top-640 的次序就是 Decoder query 轴，因此能追踪同一个 query 经 Decoder 后的框、分数及最终名次。
- 最终输出：按 Decoder 分数取 Top-300；不另加 score threshold。
- 下表的局部分解以“存在 Encoder owner”的 GT 为分母。它是逐 GT 独立覆盖诊断，不等价于 COCO/Hungarian 一对一 TP/FP。

## 结论

SGQS 后期对“附近候选池”的利用确实增强，但 **不属于强依赖火力覆盖**。e34 small 的 Top-300 成功覆盖为 70.68%，其中原 owner 直接贡献 66.46 个百分点，真正因原 owner 未直达而由其他 query 救回仅 4.22 个百分点，即成功覆盖中约 5.97% 依赖替代救援。

真正显著的变化是 score reranking：small 的原 owner 经 Decoder 后仍保持 IoU≥0.5 的比例从 e28 的 99.73% 到 e34 的 99.83%，几何没有坏；但它进入 Top-300 的比例从 71.53% 降至 66.59%，成为局部最高分的比例从 70.76% 降至 57.28%。因此 e30 以后主要问题是 Decoder 对 small owner 的降分/竞争淘汰，而不是回归必须靠大量邻近 anchor 才能成框。
